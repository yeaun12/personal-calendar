# 모여봄

친구나 모임 구성원이 가능한 날짜와 시간을 정하고, 약속 종류에 맞는 아이디어를 고르는 **프런트엔드 시제품**입니다. 밝고 아기자기한 분위기의 순수 HTML·CSS·JavaScript로 구성되어 있으며 빌드 도구나 외부 라이브러리는 필요하지 않습니다.

## 프로젝트 파일

```text
.
├── index.html              # 약속 투표와 아이디어 추천
├── workspace.html          # 모임 공간 및 초대 코드 데모
├── personal-calendar.html  # 개인 캘린더와 약속 신청 데모
├── plan.md                 # 과제 단계별 계획·설계서
├── README.md               # 프로젝트 안내
└── .gitignore              # 로컬·운영체제 파일 제외 규칙
```

## 화면

- **`index.html`** — 약속 투표 생성, 날짜 선택, 30분 단위 시간표, 날짜 탭, 응답 집계, 약속 종류별 아이디어 룰렛
- **`workspace.html`** — 이메일 기반 데모 로그인, 모임 생성, 초대 코드·링크 및 참여 화면
- **`personal-calendar.html`** — 프로필, 개인 일정 등록, 다른 데모 프로필의 가능 여부 확인, 약속 신청 및 수락·거절

## 실행 방법

별도 설치나 빌드 없이 `index.html`을 브라우저에서 열어 투표 화면을 볼 수 있습니다. 모임과 개인 캘린더의 페이지 간 데이터 흐름을 확인하려면 세 HTML 파일을 **같은 출처**에서 제공해야 합니다. 정적 웹 호스팅에 올리거나 로컬 정적 서버를 사용하세요.

## 데이터와 제한 사항

이 프로젝트는 화면과 브라우저 내 사용 흐름을 확인하기 위한 시제품입니다.

- 로그인은 이메일 주소만 사용하는 데모이며 실제 인증이나 비밀번호 기능이 없습니다.
- 모임, 프로필, 개인 일정 및 신청 정보는 브라우저의 `localStorage`에 저장됩니다. 다른 사람의 기기나 브라우저와 데이터가 공유되지 않습니다.
- 일정 투표 응답은 현재 페이지 메모리에만 유지되며 실제 공유 링크나 서버 저장 기능이 없습니다.
- 개인 일정 제목은 다른 프로필 화면에 표시하지 않도록 했지만, 이는 실제 보안·접근 제어가 아닙니다. 민감한 정보를 입력하지 마세요.
- 실제 서비스로 사용하려면 서버 인증, 데이터베이스, 서버 측 권한 검사, 개인정보 보호 검토 및 다중 사용자 테스트가 필요합니다.

## GitHub 업로드 준비

저장소 루트에 위 파일을 함께 올리면 됩니다. `.gitignore`는 운영체제·편집기 파일, 로컬 의존성/배포 캐시, 환경 변수 파일을 제외합니다. 이 프로젝트에는 현재 빌드 산출물이나 비밀 키가 필요하지 않습니다. 저장소를 공개하기 전에 올릴 파일에 개인 정보나 비밀 정보가 없는지 직접 확인하세요.

## Vercel 등 정적 호스팅

GitHub 저장소를 정적 사이트로 가져와 배포할 수 있습니다. 빌드 단계가 없는 HTML 프로젝트이므로 패키지 설치나 빌드는 필요하지 않습니다. 배포 후 기본 주소에서 `index.html`이 열리는지, 다음 페이지도 각각 확인하세요.

- `/`
- `/workspace.html`
- `/personal-calendar.html`

실제 배포를 완료하기 전에는 결과물 URL을 임의로 작성하지 마세요. 이 문서와 프로젝트 파일은 배포 자체가 완료되었음을 의미하지 않습니다.

## 개인 캘린더 데모 확인 순서

1. 같은 출처로 제공되는 환경에서 `workspace.html`을 열고 이메일 주소를 입력해 데모 로그인합니다.
2. `개인 캘린더`에서 표시 이름을 저장하고 날짜를 골라 개인 일정을 등록합니다.
3. 모임 공간으로 돌아가 로그아웃한 뒤 다른 이메일로 데모 로그인하고 두 번째 프로필을 만듭니다.
4. 두 번째 프로필에도 일정을 등록한 다음 첫 계정으로 다시 전환해 날짜별 가능 여부와 신청 흐름을 살펴봅니다.
5. 상대 계정으로 전환해 받은 신청을 수락하거나 거절합니다.

브라우저 실행과 기능 테스트는 별도로 수행하고 결과를 기록해야 합니다. README에 테스트를 완료했다고 기재하지 않았습니다.

- 여러 기기 간 일정·모임 데이터 공유
- 신청 알림, 취소 및 시간대 처리
- 개인정보 동의·보존·삭제 정책
- 기능·모바일 화면·접근성 테스트

모여봄은 일정 조율 아이디어를 바탕으로 한 독립적인 시제품이며, 다른 서비스의 이름이나 화면 디자인을 복제하지 않습니다.

## 라이선스

현재 별도 라이선스는 지정되어 있지 않습니다. 공개 저장소에서 타인이 재사용할 수 있도록 허용하려면 프로젝트 소유자와 과제 조건을 확인한 뒤 라이선스를 선택하세요.

## 과제 제출 정보

- **결과물 URL:** 실제 배포 후 주소 입력
- **소스 저장소 URL:** GitHub 저장소 생성 후 주소 입력
- **실행·테스트 결과:** 직접 실행한 뒤 사실에 맞게 작성
- **배포 여부:** 실제 배포 상태에 맞게 작성

저장소 업로드, 실행 테스트, 배포 여부는 각 작업을 완료한 뒤 별도로 확인해야 합니다.
